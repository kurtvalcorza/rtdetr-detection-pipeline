## Conformance notes

- **Standalone carrier (NOTEBOOK_SPEC 2.0 §4):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/rtdetr_detection_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 4-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD8):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files with `local_files_only=True`, `trust_remote_code=False` and `use_pretrained_backbone=False` (the config already says so; the in-library `RTDetrResNet` backbone fetches nothing). The notebook's only external dependencies are the pinned PyPI distributions and the Hub at that revision.
- **Role stages:** `validate_inputs` writes `outputs/rtdetr_detection_input_manifest.json` with the schema (80 labels, 300-query ceiling, the 640×640 resize), the ceilings, the input's observed mode and size, the threshold, the verdict, and one recorded rejection finding from the out-of-range-threshold probe; `evaluation_report` writes `outputs/rtdetr_detection_evaluation_report.json` — `sample-sanity` with one `box_iou` entry per drawn reference box, matched to same-label detections only, on the synthetic scene (the sports ball reference scores 0.0 with `n_detected_same_label` 0 — a recorded miss); `not-measurable` on BYOD (with what labelled data would make the task measurable).
- The default sample is a deterministic 640×480 scene drawn in code with Pillow (a stop sign with the word STOP, a three-lamp traffic light, an analogue clock with numerals, an orange sports ball) — the same scene the smoke run used; `box_iou` against icons you drew yourself is sanity evidence for the input contract, forward pass and coordinate mapping, not a detection metric, and drawn icons are not COCO photographs. The scene digest depends on the Pillow build's bundled font rendering and is printed, not asserted.
- Score semantics (UNC1–UNC4): every `score` is a per-class sigmoid under the model's focal-loss head, not a softmax and not a calibration for the deployment's images; the threshold is a caller-owned request parameter exposed as a `# @param` value with the package default 0.3 (the README example's value, not a calibration) and passed explicitly on every `detect` call. The notebook performs no validation of its own — image and threshold are checked only by the pipeline's `validate_inputs`/`detect` path.
- Ceilings `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_DETECTIONS` (300), the 80 `LABELS` and `DETECTION_THRESHOLD` are printed before the model runs.
- CPU is documented as adequate (card-measured 4.8 s load, 0.25–0.34 s per `detect` on the 640×480 scene; 0.52 s on a 4096×4096 blank image — which returned one `train` at 0.33, the "any image yields boxes" risk stated in the notebook).
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
