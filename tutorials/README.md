## Conformance notes

- **Standalone carrier (NOTEBOOK_SPEC 2.0 §4):** the primary path performs no clone, repository install, or repository import. Section 2 carries the package's two modules (`samples.py` and `pipeline.py`) verbatim in dependency order (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 4-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module SHA-256 digests, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD8):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files with `local_files_only=True`, `trust_remote_code=False` and `use_pretrained_backbone=False` (the config already says so; the in-library `RTDetrResNet` backbone fetches nothing). The notebook's only external dependencies are the pinned PyPI distributions and the Hub at that revision.
- **Role stages:** `validate_inputs` writes `outputs/rtdetr_detection_input_manifest.json` with the schema (80 labels, 300-query ceiling, the 640×640 resize), the ceilings, the input's observed mode and size, the threshold, the verdict, and one recorded rejection finding from the out-of-range-threshold probe; `evaluation_report` writes `outputs/rtdetr_detection_evaluation_report.json` — `sample-sanity` with one `box_iou` entry per drawn reference box, matched to same-label detections only, on the synthetic scene (the sports ball reference scores 0.0 with `n_detected_same_label` 0 — a recorded miss); `validate_dataset` validates the labelled adaptation dataset schema; `evaluate` computes COCO-style average precision across IoU thresholds 0.50 to 0.95 before and after adaptation; `save_artifact` exports `outputs/rtdetr_adapter.pt`; and `load_artifact` performs fresh reload and numerical verification.
- The default sample is a deterministic 640×480 scene drawn in code with Pillow (a stop sign with the word STOP, a three-lamp traffic light, an analogue clock with numerals, an orange sports ball), and the adaptation dataset is a deterministic 40-image synthetic sign dataset (`stop-sign`, `yield-sign`, `speed-limit-sign`).
- Score semantics (UNC1–UNC4): every `score` is a per-class sigmoid under the model's focal-loss head, not a softmax and not a calibration for the deployment's images; the threshold is a caller-owned request parameter exposed as a `# @param` value with the package default 0.3 and passed explicitly on every `detect` call.
- Ceilings `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_DETECTIONS` (300), the 80 `LABELS` and `DETECTION_THRESHOLD` are printed before the model runs.
- CPU is documented as adequate (card-measured 4.8 s load, 0.25–0.34 s per `detect` on the 640×480 scene; fine-tuning runs in ~30–50 s on CPU and ~1–2 s on GPU).
- `USE_BYOD_IMAGE` and `USE_BYOD_DATASET` default to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
